# 10_04 Child Identity & Wardrobe

아이 얼굴 풀(D-024)·의상 시스템(D-026)의 정본. 10_03 파이프라인의 확장이며, "아이를 무한에 가깝게 생성하는 방법"과 "그 비용을 감당 가능하게 만드는 구조"를 함께 정의한다.

## 1. 아이 정체성 풀 (Child Identity Pool, D-024)

- 아이는 고정 캐릭터가 아니라 **`cid_{nnn}` 정체성 풀에서 게임 시작 시 배정**된다(초기 목표 30종, 확장 가능). 플레이어마다 "내 아이"의 얼굴이 다르다 — 재플레이 가치와 "내 아이"라는 소유감의 원천.
- 각 identity는 **자기 얼굴에 맞는 성장 시트 5컷**(`age0/1/3/5/6`)을 갖는다. 성장해도 같은 아이로 보이는 것이 이 시스템의 품질 기준이다.
- 기질 시드(`temperament_seed`)와 완전 독립 — 외모와 성격을 분리해 조합 다양성을 만든다 (30 얼굴 × 3 기질 = 90 조합).

### 1.1 대량 생성 방법 — 프롬프트 매트릭스

수십 종을 "쉽게" 만드는 방법은 얼굴을 자유 서술하지 않고 **변수 조합표로 기계적으로 생성**하는 것이다.

```
얼굴 고정문(cid) = 베이스 고정문 + 눈매(3) × 얼굴형(3) × 피부톤(2) × 머리숱/머리색(2) = 36 조합
```

| 변수 | 값 |
|---|---|
| 눈매 `eye` | 처진 눈 / 둥근 눈 / 가늘고 긴 눈 |
| 얼굴형 `face` | 둥근형 / 갸름한형 / 각진형 |
| 피부톤 `skin` | 밝은 웜톤 / 중간 뉴트럴톤 |
| 머리 `hair` | 숱 적고 옅은 갈색 / 숱 많고 짙은 검정 |

- 절차: ① 조합표에서 `cid_001~036`의 얼굴 고정문을 기계 생성 → ② identity당 **기준 컷 1장**(age1 정면) 배치 생성 → ③ 선별(유사 얼굴 중복 제거, QA-10-07) → ④ 생존 identity만 성장 시트 5컷 확장.
- 확장 시 변수 하나를 추가할 때마다 풀이 배로 늘어난다 — "무한"은 조합표의 열 추가로 달성하고, 개별 수작업으로 달성하지 않는다.

### 1.2 성장 일관성 규칙

- 성장 시트 생성은 반드시 **직전 연령 컷을 이미지 레퍼런스로 첨부** + 얼굴 고정문 유지 + "같은 아이가 자란 모습" 지시로 한다 (age0→1→3→5→6 순차 체인).
- 시트 5컷을 한 화면에 나열해 "동일 인물의 성장"으로 읽히는지 검수(QA-10-08). 실패 시 해당 연령만 리테이크.
- identity별 고정 특징 1개(보조개, 쌍꺼풀 유무, 가마 위치 등)를 고정문에 명시 — 연령 간 동일성의 앵커.

### 1.3 비용 통제 — 컷 문법과 슬롯 구조 (핵심)

30 identity × 모든 장면을 생성하는 것은 불가능하다. 비용은 구조로 통제한다.

| 컷 계층 | 얼굴 노출 | 생성 단위 | 물량 |
|---|---|---|---|
| **공용 컷** (뒷모습·손·먼 거리·사물) | 없음/비식별 | **전 identity 공유 1벌** | 장면의 ~80% |
| **슬롯 컷** (감정 정점·얼굴 식별 필요) | 있음 | **identity별 생성** | 표준 슬롯 ~12개 × identity |
| 성장 시트 | 있음 | identity별 5컷 | 고정 |

- **표준 슬롯 12종(초안)**: 첫 미소(CH1), 돌잡이 순간(CH1), 첫 걸음(CH2), "엄마" 첫 말(CH2), 하원 안김(CH2), 발표회 무대(CH3), 아픈 밤(CH3), 혼난 뒤 눈물(CH4), 화해 포옹(CH4), 졸업식(CH5), 입학식 뒷모습+돌아봄(CH5), 엔딩 편지 낭독(CH5).
- 산정: identity당 5(시트) + 12(슬롯) = **17컷 × 30종 = 510컷**. 공용 컷 ~60컷은 1회만. 수동 생성으로는 상한선의 물량이므로 §3의 자동화가 전제다.
- 풀 확장은 언제나 "시트+슬롯 17컷"의 증분 비용만 발생한다.

## 2. 의상 시스템 (Wardrobe, D-026)

옷은 (1) 현실감·시간 경과의 표현이자 (2) 가계(`money`)와 연결된 플레이 요소다.

### 2.1 구조

- `outfit_def`: `otf_{age}_{name}` — age_stage별 의상 정의. 획득 경로: 기본 지급 / 마트·장보기 구매(03_02 지출 연동) / 이벤트 획득(돌잔치 한복, 물려받은 옷, 입학식 옷).
- `child_state.outfit_id`: 현재 착용 의상. 계절·이벤트에 따라 플레이어가 갈아입힘.
- 연령당 의상 수 상한 4종(기본 1 + 획득 3) — 조합 폭발 방지의 1차 상한.

### 2.2 착용 시 외관 반영 전략 (조합 폭발의 해법)

의상 × identity × 장면 전조합 생성은 불가능하다. 반영 계층을 나눈다.

| 계층 | 반영 방식 | 비용 |
|---|---|---|
| 공용 컷 | 의상 반영 **안 함** — 뒷모습·거리 컷은 실루엣이 비슷한 "기본 의상 톤"으로 통일 생성 | 0 |
| **의상 슬롯 컷** | 표준 슬롯 12종 중 **의상이 서사인 4종**(돌잡이 한복, 발표회 의상, 졸업식, 입학식)만 의상 변형 생성 | 4슬롯 × 의상 2~3종 |
| UI 반영 | 옷장·구매 화면에서는 의상 단품 이미지(`otf_*` 플랫 컷, 인물 없음)로 표시 — identity 무관 1벌 | 의상당 1컷 |
| 서사 반영 | 나머지 의상 효과는 대사·연출로 처리("새 옷이 벌써 작아졌다") — 09_UI 문장형 원칙과 동일 문법 | 0 |

- 원칙: **의상은 "항상 보이는 것"이 아니라 "중요한 날 보이는 것"** — 현실에서도 기억에 남는 옷은 돌잔치 한복과 입학식 옷이다. 이 절제가 비용 통제이자 연출 밀도다.

## 3. 생성 자동화 (10_03 §1 파이프라인의 v2 전제)

수백 컷 물량은 채팅창 수동 생성으로 감당할 수 없다. 두 경로 중 하나를 선택한다(결정 대기 D-027).

| 경로 | 방법 | 장점 | 유의 |
|---|---|---|---|
| A. 생성 API 배치 | GPT 이미지 API(또는 Grok API)에 프롬프트 매트릭스를 스크립트로 투입, `assets/raw/`에 자동 저장 + meta 기록 | 현 품질 유지, 파이프라인 연속성 | 비용 종량제, 얼굴 고정은 레퍼런스 이미지 입력 지원 여부에 종속 |
| B. 로컬 생성 (ComfyUI 계열) | 얼굴 고정 기법(IP-Adapter/InstantID류) + 배치 워크플로 | identity 고정 강력, 한계 비용 0 | 초기 셋업 학습, GPU 필요, 스타일을 현 시트와 맞추는 튜닝 필요 |

- 권장: **1차는 A로 시작**(현재 품질이 검증됨), 슬롯 컷 물량이 API 비용을 초과하는 시점에 B를 병행 도입.
- 어느 경로든 `validate` 계열과 동일하게 **생성 메타(model, prompt, seed, 일시)를 컷마다 기록**한다(10_03 §5).
