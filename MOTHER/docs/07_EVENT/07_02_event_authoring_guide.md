# 07_02 Event Authoring Guide

이벤트 콘텐츠 작성자의 작업 절차 기준. 시스템 규칙은 07_01, 감정 목표는 01_04를 전제로 한다.
절차·체크리스트 문서로 표 중심 구성 (7섹션 의무 대상 아님).

## 1. 작성 절차 (순서 고정)

| 단계 | 작업 | 산출물 |
|---|---|---|
| 1 | 소속 챕터와 감정 목표 선택 — 01_04 표에서 해당 챕터의 `emotion_tags` 중 1개 이상 선택 | `chapter`, `emotion_tags` |
| 2 | 회수 계획(`callback_plan`) 설계 — "이 선택이 어느 챕터에서 되돌아오는가" 먼저 결정 | `callback_plan` 초안 |
| 3 | 트리거 설계 — 3유형 중 선택, 조건은 07_01 조건 스키마만 사용 | `trigger` |
| 4 | 장면 작성 — 장소는 06_02 카탈로그, NPC는 06_03 카탈로그의 ID만 참조 | `scenes` |
| 5 | 선택지 작성 — 모든 choice에 `memory_tag` 부여, 효과는 트레이드오프로 설계 | `choices` |
| 6 | 메타 확정 — `event_class`, `priority`, `once`, `cooldown_days` | 완성 JSON |
| 7 | 셀프 QA — 아래 3절 체크리스트 전 항목 통과 후 제출 | 15_QA 제출 |

## 2. callback_plan (회수 계획) — 필수

Pillar 4: "회수 계획 없는 선택지는 만들지 않는다." 모든 이벤트 JSON에 `callback_plan` 필드를 의무 포함한다.

```json
"callback_plan": [
  {
    "chapter": 4,
    "memory_tag": "mem_ch1_first_smile",
    "usage_kr": "CH4 화해 장면에서 앨범 속 첫 미소 사진으로 회수"
  }
]
```

| 필드 | 규칙 |
|---|---|
| `chapter` | 회수가 일어나는 챕터. 소속 챕터보다 뒤여야 한다 (같은 챕터 내 회수는 보조로만 허용) |
| `memory_tag` | 회수에 사용할 태그. 본 이벤트 choices의 `memory_tag` 중 하나 |
| `usage_kr` | 회수 방식 1문장. "어떤 장면에서 어떤 형태로"가 드러나야 통과 |

- 회수 대상 이벤트가 아직 없으면 `usage_kr`에 계획만 적고, 해당 챕터 이벤트 제작 시 07_03류 카탈로그의 "회수 계획" 열과 교차 검증한다.
- `callback_plan`이 비어 있는 이벤트는 QA 리젝 (단, 챕터 피날레 등 회수 종착점 이벤트는 `"callback_plan": []`에 사유 주석을 카탈로그 문서에 기재).

## 3. 제출 전 체크리스트

| # | 항목 | 근거 |
|---|---|---|
| 1 | `emotion_tags`가 1개 이상이며, 전부 소속 챕터의 태그 목록(01_04)에 속하는가 | D-005 |
| 2 | 모든 `choices[]`에 `memory_tag`가 있는가 (`mem_{챕터}_{주제}` 명명) | Pillar 4 |
| 3 | `callback_plan`이 있고, 회수 챕터·방식이 구체적인가 | Pillar 4 |
| 4 | `trigger.type`이 3유형 중 하나이고 조건이 07_01 스키마를 따르는가 | D-010 |
| 5 | `scenes[].location_id`·NPC 참조가 06_02/06_03에 등록된 ID인가, 해금 챕터를 위반하지 않는가 | 06_WORLD |
| 6 | 한국 고유 맥락이 소재의 중심에 있는가 — "다른 나라 배경으로 옮겨도 똑같은가?" 검증 질문 통과 | Pillar 3 |
| 7 | 선택지 효과가 트레이드오프인가 (아래 금지 패턴 1) | Pillar 2 |
| 8 | 대본에 감정 직접 서술이 없는가 (아래 금지 패턴 2) | 01_04 |
| 9 | 감정 장면에서 수치 언급·표시 지시가 없는가 | D-004 |
| 10 | `event_id`·`choice_id`·`scene_id`가 명명 규칙(`ch{n}_ev_{nnn}`, `_c{n}`, `_s{n}`)을 따르는가 | 07_01 |

## 4. 금지 패턴

| 패턴 | 설명 | 잘못된 예 | 고치는 방향 |
|---|---|---|---|
| 정답 선택지 | 한 선택지가 모든 수치에 이득이거나 손실 없는 선택지 | "아이를 달랜다: attachment +5, 손실 없음" | 모든 선택은 자원(시간·체력·돈·관계) 중 무언가를 지불한다. 전부 잘하는 플레이 불가 (Pillar 2) |
| 감정 직접 서술 | 대본이 감정을 텍스트로 설명 | "엄마는 슬펐다", "뿌듯한 마음이 들었다" | 행동·사물로 보여준다: "젖병을 닦다가 손이 멈춘다" (01_04 금지 사항) |
| 도덕 평가 내레이션 | 선택 직후 서술자가 선택의 옳고 그름을 판정 | "그것은 좋은 선택이었다" | 판정하지 않는다. 결과는 이후 아이의 행동 변화로만 |
| 단일 분기 드라마 | 선택 1회로 극적 분기 생성 | "이 선택으로 아이 성격이 결정된다" | 성격 축은 누적으로만 변화 (D-008). 1회 효과는 ±5 이내 권장 |
| 볼륨 채우기 | 챕터 감정 목표와 무관한 이벤트 | 감정 태그가 형식적으로만 붙은 일상 퀘스트 | 01_04 검증 질문: "이 이벤트를 빼면 어떤 감정이 사라지는가" |
| 미등록 식별자 | 카탈로그에 없는 장소·NPC·태그 사용 | 임의의 `loc_cafe` 참조 | 06_02/06_03/00_04에 먼저 등록 후 사용 |

## 5. 효과(`effects`) 작성 가이드

| 대상 키 | 1회 권장 범위 | 비고 |
|---|---|---|
| `attachment`, `mind`, `stamina`, `child_condition` | -10 ~ +10 | major는 ±10, minor는 ±5 상한 권장 |
| `confidence`, `empathy`, `independence`, `expressiveness` | -5 ~ +5 | 누적 설계 전제 (D-008). 큰 값 금지 |
| `money` | 현실 물가 기준 정수(원) | 예: 돌잔치 대관 -800000. 12_DATABASE 물가 상수 참조 |
| `rel_npc_*` | -10 ~ +10 | 관계 수치 보유 NPC(06_03)만 사용 가능 |
