# AURA 종합 룰 v1 — 판정·타이밍·구현 규칙

`battle-design.md`가 "무엇이 있는가"라면, 이 문서는 "어떤 순서로 처리되는가"다.
효과 충돌·동시 발동·사망 판정을 전부 이 문서 기준으로 판정하며,
**코드는 이 문서의 번역이어야 한다.** 문서에 없는 상황이 나오면 먼저 문서를
고치고 그다음 코드를 고친다.

참고한 구조: 유희왕(황금률, 페이즈), 하스스톤(시크릿, 이벤트 큐, 죽음 일괄 처리),
MTG(상태 기반 판정). 단, **체인/우선권 없음** — 비동기 모바일 게임이므로
상대 턴 개입은 함정의 자동 발동뿐이다 (하스스톤 시크릿 모델).

---

## 0. 3대 원칙

1. **황금률** (유희왕식): 카드 텍스트가 기본 룰과 충돌하면 **카드가 이긴다.**
   "할 수 없다" 계열 효과는 "할 수 있다" 계열 효과보다 항상 우선한다.
2. **큐 원칙** (하스스톤식): 모든 효과는 **이벤트 큐**에 쌓여 선입선출(FIFO)로
   하나씩 완전히 처리된다. 처리 중 새 효과가 유발되면 큐의 맨 뒤에 붙는다.
   체인(역순 처리)은 없다.
3. **일괄 판정** (MTG식): 파괴·승패 같은 상태 판정은 효과 처리 "도중"이 아니라
   각 효과 처리가 **끝난 직후** 일괄로 수행한다.

## 1. 게임 상태 정의

게임의 전체 상태는 아래 요소로만 구성된다. (이 목록이 곧 저장/리플레이 스키마)

```
Game
├─ turn (턴 수, 현재 플레이어, 현재 페이즈)
├─ rngSeed (결정론적 난수 시드 — 리플레이/검증용)
├─ eventQueue (처리 대기 효과 목록)
└─ Player ×2
   ├─ life (0~30)
   ├─ energy (현재 / 최대)
   ├─ zones
   │  ├─ deck      (비공개, 순서 있음)
   │  ├─ hand      (본인만 공개, 최대 7)
   │  ├─ field     (캐릭터 슬롯 4, 공개)
   │  ├─ setZone   (세트 슬롯 2, 뒷면 비공개)
   │  ├─ location  (지역 슬롯 1, 공개)
   │  └─ graveyard (묘지, 공개)
   └─ flags (턴 제한 카운터: 합동기 1회 효과 사용 여부 등)
```

**존 이동 규칙**: 카드는 반드시 위 존 중 하나에만 존재한다. 존을 이동하면
이전 존에서 받은 일시 버프는 전부 사라진다 (손으로 되돌리면 리셋 — 하스스톤과 동일).

## 2. 턴 구조 (페이즈 상세)

유희왕식으로 페이즈를 명시하고, 각 페이즈에 할 수 있는 일을 고정한다.

```
[1] 개시 페이즈
    a. 최대 에너지 +1 (상한 8), 에너지 전부 회복
    b. 드로우 1장 (덱 0장이면 대신 라이프 -2)
    c. "개시 시" 효과를 큐에 등록 → 처리
    d. 빙결 등 지속 상태의 턴 카운트 감소
[2] 메인 페이즈
    - 자유 순서로: 캐릭터 소환 / 전술 발동 / 함정 세트 / 지역 전개
    - 각 행동은 하나씩 완결 처리 (행동 도중 다른 행동 불가)
[3] 전투 페이즈
    - 공격 선언은 1체씩: 선언 → 함정 체크 → 전투 처리 → 다음 선언
    - 전투 페이즈에는 소환/전술/세트 불가 (유희왕과 달리 메인 2 없음 — 단순화)
[4] 종료 페이즈
    a. "종료 시" 효과 처리
    b. 손패 7장 초과분을 초과한 쪽이 선택해 버림
    c. "이 턴 동안" 버프 소멸
```

**모드가 없는 이유**: 메인 2를 없앤 것은 "공격 후 추가 전개"라는 판단 분기를
줄여 모바일 턴 시간을 짧게 유지하기 위함. 전투 전에 모든 전개를 마쳐야 한다.

## 3. 행동 처리 절차 (원자적 행동)

모든 플레이어 행동은 아래 5단계를 완결해야 다음 행동이 가능하다.

```
① 선언   : 행동과 대상 지정 (비용 지불 가능성 검증)
② 비용   : 에너지 차감 (이 시점부터 취소 불가)
③ 유발   : 이 행동에 반응하는 효과(함정 포함)를 "세트/배치가 오래된 순"으로 큐에 등록
④ 처리   : 큐를 FIFO로 소진 (행동 본체 효과 → 유발 효과 순)
⑤ 판정   : 상태 기반 판정 (아래 5절) → 통과하면 행동 종료
```

**대상 재검증** (하스스톤식): ③~④ 사이에 대상이 사라지면(파괴·존 이동)
그 효과는 **대상 부분만 불발**되고 나머지는 처리된다.
예: "소환 시: 적 1체에 2 피해"의 대상이 함정으로 먼저 파괴됨 → 피해만 불발, 소환은 유효.

## 4. 함정 발동 규칙 (하스스톤 시크릿 모델)

- 함정은 **자동 발동**한다. 소유자가 발동 여부를 선택할 수 없다 (비동기 대응).
- 발동 타이밍: 조건이 되는 행동의 ③단계. **세트가 오래된 순서**로 발동한다.
- 같은 행동에 여러 함정이 걸리면 전부 큐에 등록되되, 앞선 함정이 조건을
  파괴하면(예: 공격자가 사라짐) 뒤 함정은 조건 재검증에 실패해 불발된다.
- 함정은 자신의 턴에는 발동하지 않는다 (상대 턴 전용).
- **정보 규칙**: 세트 카드의 정체는 발동 전까지 비공개. 단 세트 "매수"는 공개 정보.
- 동명 함정은 이미 같은 이름이 세트되어 있으면 추가 세트 불가 (하스스톤과 동일).

타이밍 정의 예시 (구현 시 이벤트명 고정):
| 함정 조건 | 발동 시점 |
|----------|----------|
| "상대가 캐릭터 소환" | 소환 행동 ③ — 소환 자체는 완료된 후, 소환 시 효과보다 **먼저** |
| "상대가 공격 선언" | 공격 선언 직후, 전투 피해 계산 **전** |
| "상대가 전술 사용" | 비용 지불 후, 전술 효과 처리 **전** (무효화 가능 시점) |

## 5. 상태 기반 판정 (매 효과 처리 후 자동 실행)

MTG의 state-based actions. 코드에서는 `checkState()` 하나로 구현하고,
**어떤 효과 처리 직후에도 반드시 호출**한다.

```
동시에 전부 검사 → 해당 항목 일괄 처리 → 변화가 있었으면 다시 검사 (고정점까지)
1. 체력 0 이하인 캐릭터 → 전부 동시에 파괴 (묘지로)
2. 파괴로 유발되는 효과("파괴될 때")를 큐에 등록
3. 라이프 0 이하인 플레이어 → 패배 (동시에 둘 다 0이면 무승부)
4. 합동기 성립/해제 갱신 (듀오 중 한 명이 사라지면 즉시 해제)
5. 지역 슬롯에 2장이 있으면 먼저 있던 지역 파괴
```

**동시 사망은 동시에 처리한다** (하스스톤식): "서로 파괴"가 순서 문제를 만들지 않도록,
사망 유발 효과의 처리 순서만 "배치가 오래된 순"으로 고정한다.

## 6. 키워드 사전 (텍스트 = 코드 계약)

카드 텍스트는 아래 키워드만 사용한다. **새 능력이 필요하면 먼저 여기에 등록한다.**
(유희왕의 재정 혼란을 피하기 위한 장치 — 미등록 표현으로 카드를 만들지 않는다)

| 키워드 | 정의 |
|--------|------|
| 소환 시: | 필드에 들어올 때 1회 유발 (전술로 재소환해도 다시 유발) |
| 개시 시: / 종료 시: | 소유자의 개시/종료 페이즈에 유발 |
| 파괴될 때: | 필드→묘지로 갈 때 유발 (손/덱으로 되돌리면 유발 안 함) |
| 속공 | 소환된 턴에 공격 가능 |
| 기습 | 속공 + 소환된 턴 상대 함정이 이 카드에 발동하지 않음 |
| 빙결(n) | n턴간 공격·능력 발동 불가. 지속 버프는 유지됨 |
| 무력화 | 공격 불가 + 능력 무효 + 합동기 성립에서 제외. 필드를 떠날 때까지 지속 |
| 벽 | 근접 태그의 기본 성질: 존재하는 동안 상대 근접 공격·직접 공격은 벽만 대상 가능 |
| 관통 | 원거리 태그의 기본 성질: 벽 무시 + 반격 피해 없음 |
| +x/+y | 공격력 +x, 체력 +y. "이 턴" 명시가 없으면 필드에 있는 동안 지속 |
| 회복(n) | 체력 회복. 최대치 초과 불가. 라이프 회복은 30 초과 불가 |
| 서치 | 덱에서 조건에 맞는 카드를 찾아 손패로. 덱은 그 후 섞는다 |

**텍스트 문법**: `[태그] 키워드. 조건: 효과 (제한).` 순서로 통일.
예: `[근접·공명] 기습. 소환 시: 상대 최고 공격력 캐릭터 1체를 무력화.`

## 7. 수치·난수 규칙

- 모든 난수(드로우 섞기, 하린 룰렛)는 `rngSeed`에서 파생 — 같은 시드 + 같은
  입력이면 같은 결과 (리플레이·서버 검증·버그 재현이 전부 이것에 달려 있다)
- 버프 적용 순서: **고정값 설정("~이 된다") → 가산(+x) → 배수(2배)** 순.
  같은 종류끼리는 적용된 순서대로. (하린 룰렛으로 순서 꼬임 방지)
- 피해와 회복은 동시 발생 시 피해 먼저.
- 라운드 제한: 30턴 도달 시 라이프 합산 판정 (무한 루프 방지).
  같은 게임 상태가 3회 반복되면 즉시 합산 판정 (교착 방지).

## 8. 구현 아키텍처 계약

룰이 꼬이는 것을 코드 구조로도 방지한다.

```
전투 모듈 구조 (P3에서 이 구조로만 구현)
├─ GameState   : 1절의 상태 트리. 직렬화 가능해야 함 (JSON in/out)
├─ Action      : 플레이어 입력 6종만 존재
│                summon / playTactic / setTrap / playLocation / attack / endTurn
├─ reduce(state, action) → newState
│                순수 함수. 3절의 5단계를 구현. UI·연출 코드 절대 금지
├─ EventQueue  : 2대 원칙의 큐. 효과는 전부 여기서만 처리
├─ checkState  : 5절 판정. reduce 내부에서 효과 처리 후마다 호출
└─ CardDB      : 카드는 데이터(JSON), 능력은 키워드 핸들러 참조로만 구성
```

### 카드 데이터 스키마 (카드에 코드를 넣지 않는다)

```json
{
  "id": "sera-UR",
  "type": "character",
  "cost": 7, "atk": 5, "hp": 5,
  "tags": ["melee", "resonance"],
  "abilities": [
    { "trigger": "onSummon", "effect": "neutralize", "target": "enemyHighestAtk" },
    { "keyword": "ambush" }
  ]
}
```

- `trigger` / `effect` / `target`은 6절 키워드 사전에 등록된 값만 허용.
  등록 안 된 값이 들어오면 **로드 시점에 에러** (런타임에 조용히 넘어가지 않기).
- 신규 카드 추가 = JSON 추가. 신규 메커니즘 추가 = 사전 등록 + 핸들러 구현 + 룰 문서 갱신.

### 테스트 규칙

- 6절의 키워드마다 유닛 테스트 1개 이상 (키워드 = 테스트 단위)
- 함정 × 행동 조합은 4절의 표를 그대로 테스트 케이스로 옮긴다
- 밸런스 검증: 시드 고정 봇전 1000판 자동 시뮬레이션 → 캐릭터별 픽률/승률 로그

## 9. 판례집 (엣지 케이스 선례)

애매한 상황은 여기 쌓는다. 유희왕의 "재정"에 해당하며, 코드보다 먼저 기록한다.

1. **세라 UR vs 다인 UR**: 세라의 "무력화"는 다인의 "함정 보호" 능력도 무효로
   한다. 무력화는 능력 무효이고, "할 수 없다"보다 "무효"가 상위 개념.
2. **기습 소환 vs 우천 매복**: 기습 캐릭터에는 소환 반응 함정이 발동하지 않는다.
   (키워드 정의대로. 함정은 조건 검증 단계에서 불발)
3. **리유 2회 공격 + 빙결**: 1회 공격 후 빙결되면 남은 공격권은 소멸.
4. **미소 전체 회복 + 동시 사망**: 회복은 효과 처리, 사망은 판정 단계.
   같은 큐 항목 안에서는 회복이 먼저 적용되어 사망을 면할 수 있다.
5. **합동기 성립 중 한 명 무력화**: 판정 4번에 의해 합동기 즉시 해제.
   해제로 잃은 버프는 복귀해도 재적용된다 (상태이므로).

## 10. 문서 우선순위

충돌 시: **rules.md(본 문서) > battle-design.md > game-design.md**.
카드 개별 텍스트는 황금률에 따라 그 무엇보다 우선하되,
6절 사전에 없는 표현을 쓴 카드는 존재할 수 없다.
