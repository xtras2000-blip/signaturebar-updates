# 00_03 Documentation Pipeline

## 1. 파일 규칙

- 파일명: `{디렉터리번호}_{문서번호}_{snake_case_topic}.md` (예: `05_02_growth_state_machine.md`)
- 번호는 고정이며 재사용하지 않는다. 폐기 시 99_ARCHIVE로 이동하고 번호는 결번 처리한다.
- 한 파일 = 한 주제. 300줄을 넘으면 분할을 검토한다.
- 본문은 한국어, 코드·식별자·JSON 키는 영어 snake_case.

## 2. 메커닉 문서 필수 목차

모든 시스템/메커닉 문서는 아래 7개 섹션을 이 순서로 포함한다.

```markdown
## Purpose        — 이 메커닉이 전달하려는 감정과 역할
## Variables      — 변수명, 타입, 범위, 초기값 표
## State Machine  — 상태 목록, 전이 조건, 다이어그램(mermaid)
## UI             — 노출 화면, 위젯, 피드백
## Database       — 저장 대상 테이블/필드
## JSON           — 데이터 포맷 예시 (실제 유효한 JSON)
## QA             — 테스트 케이스, 엣지 케이스
```

## 3. 동기화 규칙

- 변수 추가/변경 시: 03(시스템) → 12(DB) → 13(JSON) → 15(QA) 순으로 같은 커밋 안에서 갱신한다.
- 이벤트 추가 시: 07(이벤트) → 08(대사) → 13(JSON) 동기화.
- 상충 발견 시 상위 번호 디렉터리 문서가 우선하며, DECISION_LOG.md에 해소 결과를 기록한다.

## 4. 커밋 규칙

- 커밋 단위: 하나의 문서 주제 또는 하나의 동기화 묶음.
- 커밋 메시지: `docs(디렉터리): 요약` (예: `docs(05_CHILD): 성장 상태 머신 v1`)
